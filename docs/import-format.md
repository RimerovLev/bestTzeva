# Формат импорта каталога (T-4.2.1)

`POST /api/v1/admin/products/import` (MANAGER/ADMIN), multipart:
- `file` — CSV (UTF-8, разделитель `,`, первая строка — заголовки) или XLSX (первый лист).
- `dry_run` — `true` (по умолчанию): только валидация и отчёт; `false`: применить.

## Колонки (одна строка = один вариант)

| Колонка | Обяз. | Описание |
|---|---|---|
| `product_sku` | да | SKU товара; существующий — переиспользуется, иначе создаётся |
| `category_slug` | да | slug существующей категории |
| `brand_slug` | да | slug существующего бренда |
| `paint_type` | да | INTERIOR/EXTERIOR/WOOD/METAL/PRIMER/ENAMEL/OTHER |
| `usage_area` | нет | по умолчанию INDOOR |
| `finish` | нет | по умолчанию MATTE |
| `base_type` | нет | по умолчанию WATER |
| `name` | да | название товара (локаль he) при создании |
| `variant_sku` | да | SKU варианта; существующий — обновляется, иначе создаётся |
| `color_code` | да | код цвета (напр. RAL9010) |
| `volume_liters` | да | объём, число |
| `price` | да | цена, число |

## Поведение

- **Сопоставление по SKU**: товар по `product_sku`, вариант по `variant_sku` — обновление, не дубль.
- **dry-run**: считает created/updated/skipped и собирает ошибки, ничего не пишет.
- **Построчная транзакция**: одна плохая строка (неизвестная категория/бренд, нечисловой объём/цена,
  пустое обязательное поле) уходит в `errors` с номером строки, остальные применяются.
- **Денормализация** (`min_price/max_price/has_stock`) поддерживается statement-level триггерами (V33)
  — импорт делает обычные insert/update вариантов, триггеры срабатывают, обхода нет (R-49).
- **Большие файлы** асинхронно (задача + статус) — точка расширения; в ядре синхронно.

## Ответ

```json
{ "dry_run": true, "created": 10, "updated": 2, "skipped": 1,
  "errors": [ { "row": 5, "reason": "unknown category_slug: paints" } ] }
```
