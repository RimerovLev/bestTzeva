# Калькулятор стоимости покраски (T-11.2)

Предварительная оценка стоимости услуг. **Всегда оценка, не окончательная цена** — итог определяется
после замера на объекте (флаг `is_estimate` + оговорка на локали запроса).

## Где что

- **`service.pricing.PricingCalculator`** — чистая арифметика, без Spring и БД: на вход
  `PricingInput` + `Ruleset`, на выход `PricingResult` с разбивкой. Единственное место, где считаются
  деньги; покрыто быстрыми юнит-тестами (`PricingCalculatorTest`).
- **`service.service.PricingService`** — собирает тарифы и коэффициенты из БД в `Ruleset` и
  делегирует калькулятору; добавляет оговорку.
- **API**: `POST /api/v1/service-requests/calculate` (публичный) — диапазон, разбивка по видам работ,
  `is_estimate`, оговорка.
- **Admin**: `GET/PUT /api/v1/admin/pricing-rules` — CRUD тарифов (MANAGER/ADMIN, в audit_log).
- Оценка **снимком** пишется в заявку при создании (`estimated_price_min/max`); изменение тарифа
  позже её не меняет (проверено тестом).

## Формула площади стен (обоснование)

Точная площадь стен зависит от формы помещения, которую на этапе заявки не знаем. Оцениваем из
площади пола `S` и высоты потолков `h`:

```
периметр ≈ 4 · √S          (точно для квадрата; для вытянутых комнат периметр больше)
площадь стен ≈ периметр · h = 4 · √S · h
```

Для квадратного помещения оценка точна; для вытянутых прямоугольников реальный периметр больше, то
есть формула даёт **нижнюю** оценку площади. Погрешность формы закладывается в разброс `min–max`
тарифа (диапазон ставок ₪/м²), поэтому итог — диапазон, а не одно число.

Расчётная площадь по видам работ:

| Вид работ | Базис площади |
|---|---|
| `WALLS`, `FACADE` | `4·√S·h` (площадь стен/фасада) |
| `CEILING` | `S` (площадь пола = потолка) |
| `WOOD`, `METAL`, `DECORATIVE` | `0.15·S` (доля пола под акцентные элементы) |

## Тарифы и коэффициенты

- **`service_pricing_rules`** (тип объекта × вид работ): `price_per_sqm_min/max`, `min_order_price`.
  Seed в V42 — базовые ставки с наценкой по типу объекта (квартира 1.0 … коммерция 1.3).
- **`service_pricing_coefficients`** (V42): множители `CEILING_HEIGHT_OVER_3M` (1.2, при высоте >3 м),
  `URGENCY` (1.3), и опции `OPT_FURNITURE_REMOVAL`/`OPT_SURFACE_PREP`/`OPT_PRIMING`/`OPT_HEIGHT_WORK`.
  Отсутствующий коэффициент трактуется как нейтральный (×1).

## Порядок расчёта

1. По каждому выбранному виду работ: `базис · ставка_min` и `базис · ставка_max`, домножить на общий
   множитель (высота >3 м, срочность, опции).
2. Сумма по видам работ.
3. Минимальная стоимость заказа: если сумма ниже `max(min_order_price)` выбранных тарифов — поднять до
   неё.
4. Округление: `min` вниз до 10 ₪, `max` вверх до 10 ₪ (диапазон консервативен).

## Тесты

`PricingCalculatorTest` (юнит): базовый расчёт, коэффициент высоты, срабатывание минимальной
стоимости, границы округления, опции+срочность. `PricingApiTest`: API-ответ с разбивкой и оговоркой,
влияние типа объекта, снимок оценки в заявке не меняется при изменении тарифа.
