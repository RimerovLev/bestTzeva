# Стратегия тестирования (T-14.3)

## Пирамида

1. **Юнит** — быстрые, без Spring/БД: калькулятор стоимости (`PricingCalculatorTest`), сегментатор
   SMS (`SmsSegmenterTest`), тихие часы (`QuietHoursPolicyTest`), маскирование логов
   (`LogMaskerTest`).
2. **Интеграционные** — сервисы и репозитории через Testcontainers (Postgres 16, Redis 7, MinIO):
   резервы, движения, каталог, заявки, уведомления, приватность.
3. **API** — контроллеры через `TestRestTemplate` (реальный HTTP, security, валидация).
4. **Сквозные** — ключевые бизнес-пути целиком (`EndToEndFlowTest`).
5. **Инвариантные/архитектурные** — журнал остатков (`StockJournalInvariantTest`), границы модулей и
   доступ к таблице inventory (ArchUnit), применение миграций (`MigrationValidateTest`).

## Обязательные сквозные сценарии

- Гость отправляет заявку на товар → менеджер резервирует позиции → закрывает (COMPLETED, продажа).
- Резерв истекает по сроку → остаток возвращается, заявка → LOST.
- Админ создаёт товар → он в каталоге с ценой и наличием → попадает в заявку.
- Клиент отправляет заявку на покраску → менеджер выставляет котировку.
- Сотрудник склада проводит приход и инвентаризацию.

## Покрытие (JaCoCo)

- Порог: **70%** строк по проекту, **85%** для `com.tzevabest.inventory.*` и
  `com.tzevabest.request.*`. Исключены DTO, мапперы, конфигурации, доменные сущности, планировщики,
  dev-сидер.
- `./gradlew check` падает при недоборе (`jacocoTestCoverageVerification`).

## Мутационное тестирование (PIT)

- PIT нацелен на калькулятор стоимости (`com.tzevabest.service.pricing.*`, быстрые чистые тесты).
  Gradle-плагин PIT пока несовместим с Gradle 9, поэтому запускается отдельным шагом на
  Gradle-совместимой конфигурации или standalone-PIT в CI. Пакет `inventory` покрыт интеграционными
  тестами (Testcontainers) — PIT по нему точечно и вне обычной сборки (долго).

## Инвариант журнала

`StockJournalInvariantTest`: после произвольной последовательности из 20 операций
`sum(qty_delta) == inventory.qty` и `sum(reserved_delta) == reserved_qty` по каждому складу.
Проверяется постоянно (следствие R-41), а не один раз.
