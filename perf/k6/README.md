# Нагрузочные сценарии k6 (T-14.5)

Запуск (k6 установлен, приложение доступно по `BASE_URL`):

```bash
BASE_URL=https://staging k6 run perf/k6/browse.js   # read-heavy, до 200 VU, плато 10 мин
BASE_URL=https://staging k6 run perf/k6/peak.js      # пик 500 VU за 30с
```

- `browse.js` — 75% листинг / 20% карточка / 5% поиск; пороги p95 в самом сценарии.
- `peak.js` — рекламный пик на главную и категорию.
- **Конкуренция за остаток** (100 параллельных резервирований последней единицы) проверяется
  интеграционно и на корректность, а не только на скорость: см.
  `InventoryReservationTest.concurrent_reservations_for_last_can_leave_exactly_available` и
  `crossing_reservations_do_not_deadlock` (условный атомарный UPDATE, детерминированный порядок
  блокировок). k6-скрипт для админского резерва требует staff-токенов и запускается точечно.

Реальный прогон — на окружении, сопоставимом с продовым (вне среды разработки).
